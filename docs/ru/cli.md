# Командная строка

> Перевод [cli.md](../cli.md) на коммит `ba129a5`. Если перевод расходится с английской версией, верна английская.

`tele` без команды открывает окно. Все команды и их флаги описаны в
[commands.md](commands.md). Эта страница описывает договорённости, которые
соблюдают все команды: как они названы, с каким кодом завершаются и как выглядит
их JSON.

<a id="a-command-needs-a-tele-to-ask"></a>
## Команде нужен `tele`, которого можно спросить

Команда обращается к `tele`, который держит аккаунт: к открытому окну или к
сервису. Своего `tele` она никогда не запускает. Если ни один не запущен, она
завершается с кодом 3 и подсказывает, как его получить: открыть `tele` или
установить сервис через `tele daemon install`. Поэтому для скриптов нужен
сервис: он работает с момента входа в систему, открыто окно или нет. См.
[Работа без окна](configuration.md#running-without-a-window).

Работающая команда не считается человеком, который смотрит в аккаунт: она не
мешает показать системное уведомление, а окно при выходе не считает её среди
окон, которые закроются вместе с ним.

<a id="how-commands-are-named"></a>
## Как названы команды

1. Команды верхнего уровня действуют в Telegram; поддерево `daemon` действует на
   `tele`, который держит аккаунт.
2. Команды называются целыми словами: никаких `tele ls` и `tele d`.
3. Длинные флаги пишутся с двумя дефисами, `--name`. Короткая форма есть только
   у того, что набирают руками: `-c` для `--config`, `-h` для `--help`, `-e` для
   `--debug`.
4. У флага, действие которого трудно отменить, короткой формы нет.
5. Вывод для программ включается флагом `--json`, в каждой команде, где он
   есть.
6. Одно и то же значение называется одинаково во всех командах, например
   `--limit`.
7. Чат во всех командах указывается одинаково.
8. Действие оформляется командой, а флаг только уточняет её. Поэтому `tele version` и
   `tele theme check`, а не `--version` и `--theme-check`. Эти два флага и
   `--theme-dump` по-прежнему работают для пакетных менеджеров, которые их
   вызывают, но в справке не предлагаются.

<a id="exit-codes"></a>
## Коды завершения

| Код  | Значение                                                                        |
| ---- | ------------------------------------------------------------------------------- |
| 0    | Готово                                                                          |
| 1    | Что-то другое пошло не так; что именно, сказано в stderr                        |
| 2    | Не удалось разобрать командную строку: неизвестный флаг, команда или аргумент   |
| 3    | Нет `tele`, который держит аккаунт и которого можно спросить                    |
| 4    | В аккаунт не выполнен вход                                                      |
| 5    | Нет такого чата или темы                                                        |
| 6    | Сообщение не удалось отправить, и повторная попытка этого не изменит            |
| 75   | Ожидание прервано, пока сообщение ещё стояло в очереди, или Telegram попросил подождать; позже может получиться |

Коды 4, 5, 6 и 75 зарезервированы за командами, которые действуют в аккаунте
(список чатов, чтение и отправка). Они появятся в одном из следующих релизов.
Скрипт сможет отличить 75, при котором стоит попробовать позже, от 6, при
котором не стоит.

<a id="json"></a>
## JSON

- Для программ есть единственный формат, `--json`. Для YAML: `| yq -P`.
- Команда, которая отвечает одним объектом, печатает один объект. Команда,
  которая отвечает списком, печатает JSON Lines: по объекту на строку, от
  старых к новым там, где порядок означает время.
- Имена полей в `snake_case`. Время в формате RFC 3339.
- Поле, которое неприменимо, не выводится вовсе, а не выводится как ноль или
  null. Скрипт читает отсутствующее поле как «нет», а не как «ноль».
- Всё описанное здесь сохраняется в пределах мажорной версии: поля могут
  добавляться, но ни одно не будет переименовано или удалено до tele 3.
- Если команда завершилась с ошибкой, stdout остаётся пустым: причину сообщают
  код завершения и stderr.

<a id="tele-daemon-status---json"></a>
## `tele daemon status --json`

```json
{
  "state_dir": "/home/ada/.local/state/tele",
  "host": {"binary": "2.0.0", "protocol": 5, "pid": 4242, "kept": "service", "config": "/home/ada/.config/tele/config.yml"},
  "since": "2026-10-21T09:00:00Z",
  "windows": 1,
  "commands": 0,
  "account": {
    "phase": "ready",
    "user": "ada",
    "link": "up",
    "link_since": "2026-10-21T09:00:04Z",
    "last_update": "2026-10-21T12:41:10Z",
    "outbox": 0,
    "throttle": {"method": "messages.getHistory", "until": "2026-10-21T12:41:42Z"}
  },
  "this": {"binary": "2.0.0", "protocol": 5},
  "service_warning": "The service runs /opt/homebrew/bin/tele, which is not there any more."
}
```

| Поле               | Что это                                                                                        |
| ------------------ | ---------------------------------------------------------------------------------------------- |
| `state_dir`        | Каталог состояния, о котором спрашивали                                                        |
| `host`             | `tele`, который его держит: версия, протокол, id процесса, файл конфигурации и `kept`: `window`, `daemon` или `service` |
| `since`            | Когда этот `tele` запустился                                                                   |
| `windows`          | Сколько окон к нему подключено                                                                 |
| `commands`         | Сколько других команд обращаются к нему прямо сейчас                                           |
| `account`          | Аккаунт; отсутствует в промежутке между одним аккаунтом и следующим                            |
| `account.phase`    | `connecting`, `logging_in`, `loading` или `ready`                                              |
| `account.user`     | Username пользователя, под которым выполнен вход; отсутствует, пока Telegram его не сообщил, или если username нет |
| `account.ended`    | Чем закончилось соединение; отсутствует, пока оно работает                                     |
| `account.link`     | `up`, `down` или `unknown`; с какого момента, показывает `link_since`                          |
| `account.last_update` | Когда пришло последнее обновление от Telegram                                               |
| `account.outbox`   | Сколько сообщений ждут отправки                                                                |
| `account.throttle` | Ожидание, о котором попросил Telegram и которое что-то задерживает, и до какого момента; отсутствует, если ожидания нет |
| `this`             | `tele`, который спрашивал: его версия и протокол                                               |
| `service_warning`  | Что не так с установленным сервисом; отсутствует, если всё в порядке                           |

`tele`, который говорит на другой версии протокола, только называется: есть
`host` и `this`, и ничего сверх того, о чём его спросили. Если каталог
состояния никто не держит, ничего не печатается, а код завершения 3.
